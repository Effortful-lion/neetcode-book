# 树\-DFS

前序、中序、后序遍历的选择，核心取决于\\*\\*“处理当前节点的逻辑是否依赖子树的结果”\\*\\*，以及\\*\\*代码的直观性\\*\\*。以下从“问题适配度”和“理解性”两个维度总结选择原则：

#### 一、按“问题需求”选择：核心看“当前节点的处理时机”

##### 1\. 前序遍历（根 → 左 → 右）：适合“根节点不依赖子树”的场景

- **核心特征**：先处理当前节点，再递归子树。当前节点的逻辑不依赖左/右子树的计算结果。

- **适配问题**：

- **创建/复制结构**：如深拷贝二叉树（先复制根，再复制左右子树）、根据遍历序列构建树（前序序列可作为“根”的标记）。

- **记录路径/状态**：如打印从根到叶子的路径（先记录当前节点，再递归子树）、计算路径和（先累加当前节点值，再递归子树）。

- **初始化操作**：如给节点添加父指针（先处理根的父指针，再处理子树）。

- **理解性**：直观，符合“从根开始扩散”的思维习惯，代码逻辑与“操作顺序”一致，容易调试。

##### 2\. 中序遍历（左 → 根 → 右）：适合“根依赖左子树”的场景

- **核心特征**：先递归左子树，再处理当前节点，最后递归右子树。当前节点的逻辑依赖左子树的结果，但不依赖右子树。

- **适配问题**：

- **二叉搜索树（BST）操作**：BST的中序遍历是有序序列，适合找第k小元素、验证BST（左子树都小于根，根小于右子树）、求前驱/后继节点。

- **依赖左子树状态的计算**：如按“左根右”顺序拼接字符串（左子树拼接完才能拼根）、计算节点在中序序列中的位置。

- **理解性**：逻辑链条清晰（左子树→根→右子树），尤其在BST场景中，与“有序性”天然契合，容易理解。

##### 3\. 后序遍历（左 → 右 → 根）：适合“根依赖左右子树”的场景

- **核心特征**：先递归左、右子树，再处理当前节点。当前节点的逻辑依赖左右子树的计算结果。

- **适配问题**：

- **计算树的属性**：如树的高度（依赖左右子树高度）、节点总数（依赖左右子树节点数）、最大路径和（依赖左右子树的最大路径）。

- **释放资源/删除操作**：如删除二叉树（先删左右子树，再删根，避免悬空指针）。

- **验证平衡性**：判断平衡二叉树（依赖左右子树的高度差）。

- **理解性**：需要“先处理子树，再汇总结果”的思维，初期可能觉得绕，但在“依赖子树结果”的场景中，逻辑严谨性最高。

#### 二、按“理解性”选择：优先直观性

- **优先选前序**：如果问题中“根节点的操作”是第一步（如创建、初始化），前序最直观，代码与思维顺序一致（先做根的事，再处理子树）。

- **优先选中序**：涉及BST或“左→根→右”的顺序依赖（如有序序列），中序的逻辑链条最自然，不容易出错。

- **优先选后序**：当问题明确需要“子树的结果”才能处理根（如计算高度、判断平衡），后序是唯一选择，虽然需要多一层“等待子树处理”的思维，但逻辑最贴合问题本质。

#### 三、总结：选择流程图

```Plain Text
问题是否需要“子树的结果”才能处理当前节点？
├─ 不需要（根操作独立）→ 前序遍历
├─ 需要“左子树结果”，但不需要“右子树”→ 中序遍历
└─ 需要“左右子树结果”→ 后序遍历
```

**示例**：

- 复制二叉树：不需要子树结果（先复制根）→ 前序。

- 验证BST：需要左子树都小于根 → 中序。

- 计算树高：需要左右子树高度 → 后序。

按这个逻辑选择，既能保证代码正确性，又能最大化理解性，减少思维负担。

## 系统

以下是关于二叉树 **DFS（深度优先搜索）** 及 **前序、中序、后序遍历** 的系统整理，包括核心概念、区别、联系及应用场景：

#### 一、核心概念

1. **DFS（深度优先搜索）**

一种遍历策略：优先沿着树的深度遍历节点，直到某条路径的叶子节点，再回溯到上一层继续遍历其他路径。

二叉树中，DFS 的具体实现形式就是 \\*\\*前序、中序、后序遍历\\*\\*，三者的区别仅在于 \\*\\*“处理当前节点（根节点）的时机”\\*\\*。

1. **前序遍历（Pre\-order）**

- **顺序**：根 → 左子树 → 右子树

- **核心**：先处理当前节点，再递归遍历左右子树（当前节点的逻辑不依赖子树）。

1. **中序遍历（In\-order）**

- **顺序**：左子树 → 根 → 右子树

- **核心**：先递归遍历左子树，再处理当前节点，最后遍历右子树（当前节点的逻辑依赖左子树结果）。

1. **后序遍历（Post\-order）**

- **顺序**：左子树 → 右子树 → 根

- **核心**：先递归遍历左右子树，再处理当前节点（当前节点的逻辑依赖左右子树结果）。

#### 二、三者的联系与区别

\| **维度** \| 前序遍历 \| 中序遍历 \| 后序遍历 \|

\|\-\|\-\|\-\|\-\|

\| **处理顺序** \| 根 → 左 → 右 \| 左 → 根 → 右 \| 左 → 右 → 根 \|

\| **依赖关系** \| 根不依赖子树 \| 根依赖左子树 \| 根依赖左右子树 \|

\| **递归框架** \| 处理根 → 左递归 → 右递归 \| 左递归 → 处理根 → 右递归 \| 左递归 → 右递归 → 处理根 \|

\| **典型应用** \| 复制树、记录路径 \| BST有序操作、前驱查找 \| 计算高度、判断平衡 \|

\| **理解难度** \| 直观（先根后子） \| 中等（左根右顺序） \| 稍复杂（先子后根） \|

#### 三、DFS 与前中后序的关系

- **包含关系**：前序、中序、后序遍历是二叉树 DFS 的 \\*\\*三种具体实现\\*\\*，均遵循“深度优先”策略。

- **变种本质**：实际问题中的 DFS 代码（如计算树高、验证 BST）都是这三种遍历的变种——在遍历框架中嵌入业务逻辑（如计算、判断、修改节点）。

#### 四、应用场景选择指南

1. **选前序遍历**：

当“处理当前节点”不需要子树的结果，且逻辑上应先操作根节点时：

- 复制/创建二叉树（先复制根，再复制子树）。

- 记录从根到叶子的路径（先记录根，再递归子树）。

- 生成前缀表达式（根为运算符，先处理运算符）。

1. **选中序遍历**：

当“处理当前节点”依赖左子树的结果，且需按“左→根→右”顺序处理时：

- 二叉搜索树（BST）操作（中序遍历为有序序列，用于验证 BST、找第 k 小元素）。

- 求节点的前驱（左子树最右节点）和后继（右子树最左节点）。

1. **选后序遍历**：

当“处理当前节点”必须依赖左右子树的结果时：

- 计算树的高度（当前高度 = max\(左高, 右高\) \+ 1）。

- 判断平衡二叉树（需先知道左右子树高度差）。

- 释放树的资源（先释放子树，再释放根节点）。

#### 五、代码示例（递归实现）

```Go
type TreeNode struct {
    Val   int
    Left  *TreeNode
    Right *TreeNode
}

// 前序遍历
func preorder(root *TreeNode, res *[]int) {
    if root == nil {
        return
    }
    *res = append(*res, root.Val) // 处理根
    preorder(root.Left, res)      // 左子树
    preorder(root.Right, res)     // 右子树
}

// 中序遍历
func inorder(root *TreeNode, res *[]int) {
    if root == nil {
        return
    }
    inorder(root.Left, res)       // 左子树
    *res = append(*res, root.Val) // 处理根
    inorder(root.Right, res)      // 右子树
}

// 后序遍历
func postorder(root *TreeNode, res *[]int) {
    if root == nil {
        return
    }
    postorder(root.Left, res)     // 左子树
    postorder(root.Right, res)    // 右子树
    *res = append(*res, root.Val) // 处理根
}
```

#### 六、总结

- **本质**：前中后序是 DFS 在二叉树中的具体实现，核心区别是“处理根节点的时机”。

- **选择原则**：根据“当前节点的逻辑是否依赖子树结果”判断——不依赖选前序，依赖左子树选中序，依赖左右子树选后序。

- **变种应用**：实际问题中，只需在三种遍历框架中嵌入业务逻辑，即可解决大多数二叉树 DFS 问题。

## kmp是解决什么问题的？

kmp是解决字符串匹配的。简单的说，我们需要解决两个字符串（或者本身和本身）的字符串相等匹配的问题。比如：判断A串是否包含B串（或者B串在A串的开头索引位置StrStr\(\)函数）、求字符串前后缀的问题（最长相等前后缀的长度？所有相等前后缀？）

## kmp解决问题的核心作用？

在字符串匹配时，我们会遇到无法匹配的时候。比如：

> 字符串 aabaaf 和 aabaabaaf ，这两个字符串进行匹配。前者为模式串，后者为匹配串。当比较到匹配串的第二个`b`时发现有冲突。暴力解法：直接从匹配串的第二个字符开始重新匹配。
> 
> 

kmp的作用就是减少移动次数和重复比较次数。简单的说，从之前匹配的部分中找到最近的开始再次匹配。

\<callout emoji="🍞"\>

趣味解释：

当比较到匹配串的第二个`b`时发现有冲突，这个`b`和`f`不相等。`f`说：说明我前面的相等。我发现前面`aabaa`有两个相等的（就是`aa`）。我这里冲突了，但是那`b`和我一样，前面都是`aa`，我让他来匹配一下子。（这里相当于整个字符串向后移动了`len("aa")+1`个位置，比之前的`1`个位置多，减少了移动次数。同时前面的`aa`不用再比较了。）这`b`匹配成功了，真好！我来看看后面有没有也和我长得一样的！最后`f`也看到了自己，kmp的故事结束了。

\</callout\>

## 怎么实现kmp算法？（需要克服哪些问题）

总的思想：我需要找到前面一个”替罪羊“。也就是说，我需要找到冲突字符的前面最长的相等前后缀。中间夹着的（前缀后面的）就是那个”替罪羊“。

1. 怎么求字符串的前缀表

2. 怎么找到替罪羊（前缀后一个字符）的位置

### 怎么求字符串的前缀表

这里有两种解法：以当前字符为结尾的字符串的前缀表、当前字符之前的字符串的前缀表

以当前字符为结尾的字符串的前缀表

> aabaaf
> 
> 

1. a 是一个字符，没有前后缀 。0

2. aa 的前后缀为 a 。1

3. aab 的前后缀。0

4. aaba 的前后缀 a 。1

5. aabaa 的前后缀 aa 。2

6. aabaaf 的前后缀。0

所以 前缀表为 010120

当前字符之前的字符串的前缀表

1. a之前没有字符串为空 \-1

2. 第二个a之前有一个字符串a，a 是一个字符，没有前后缀 0

3. b之前有一个字符串aa，aa 的前后缀为 a 1

4. 第三个a之前有一个字符串aab，aab 没有前后缀 0

5. 第四个a之前有一个字符串aaba，aaba 有前后缀 1

6. f 之前有一个字符串aabaa，aabaa 有前后缀 2

所以 前缀表为 \-101012

### 怎么找到替罪羊（前缀后一个字符）的位置

我们发现：

f是最后一个位置：

1. 以当前字符为结尾的字符串的前缀表：为 010120

1. 他的前一个字符串的最长相等前后缀长度为2（存在前一个字符`a`位置的前缀表）

2. 我们找到的替罪羊就在索引为2的位置

3. 当前字符之前的字符串的前缀表：为 \-101012

1. 他的前一个字符串的最长相等前后缀长度为2（就在f位置的前缀表）

2. 我们找到的替罪羊就在索引为2的位置

## 代码实现（各种子问题、扩展问题）

### 怎么求字符串的前缀表

我们就用第一种吧！以当前字符为结尾的字符串的前缀表（可以叫 prefix 或者 next）

```Go
package main

import (
    "fmt"
)

func main(){
    str := "aabaaf" // 010120
    res := getPrefix(str)
    fmt.Println(res)
}

func getPrefix(str string) []int{ 
    prefix := make([]int, len(str))
    if len(str) == 0 { // 处理空字符串边界 case
        return prefix
    }
    prefix[0] = 0
    // i 表示后缀结尾：既表示我们遍历/求的位置，也表示后缀结尾
    // j 表示前缀结尾：用来和i做比较，记录前缀长度
    // 注意： j:=0 必须要在for外面，因为j一直记录的是最长的前缀长度，不能每次都从0开始
    j:=0
    for i:=1;i<len(str);i++{
        // i从1开始，因为一个字符没有前后缀，已经初始化了
        // 可能不是一步匹配
        for j>0 && str[j]!=str[i]{
            // j 需要回退：根据自身的prefix表，随时填充，随时使用的
            j=prefix[j-1]
        }    
        // str[j] == str[i] || j == 0
        if str[j] == str[i]{
            j++
        }
        prefix[i] = j
        // i++ for循环自然++
    }
    return prefix
}
```

// 求StrA和StrB的相等部分开头索引
func KMP(strA, StrB string) int{
    prefix := getPrefix(StrB)
    // i j 分别作为 匹配指针
    j := 0
    res := -1
    for i:=0;i<len(strA);i++{ 
        for j > 0 && strA[i] != StrB[j] { // 匹配失败
            j = prefix[j-1] // 回退
        }
        // 匹配成功
        if strA[i] == StrB[j] {
            j++
            if j == len(StrB) { 
                // 全部匹配成功
                res = i - j + 1
                break
            }
        }
    }
    return res
}

### 重复的子字符串

```Go
// 暴力
func repeatedSubstringPattern(s string) bool {
    n := len(s) // ok
    for i:=0;i<n;i++{ //ok
    // for i:=0;i<n/2;i++ // 自然就倍数>1了
        leni := i+1 // i+1  ok

        // 长度一定是整数倍 并且 倍数>1
        num:=n/leni 
        if n%leni!=0 || num<=1{
            continue
        }                   // ok

        // 如果ok
        str1 := s[:leni]    // ok
        count := 0
        for j:=1;j<num;j++{
            // 重复多少次，就 * 多少
            // 用start end定位字符串
            start := j*leni
            end:=start+leni
            str2 := s[start:end]
            if str2==str1{
                count++
            }else{
                break
            }
        }
        if count==num-1{
            return true
        }
    }
    return false
}
```

    n := len(s)

    // next[n-1]  最长相同前后缀的长度
    if next[n-1] != 0 && n%(n-next[n-1]) == 0 {
        return true
    }
    return false
}
